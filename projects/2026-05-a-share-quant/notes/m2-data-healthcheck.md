## 2. 逐项诊断

### 项 1 · 股票覆盖：100 只无日线 → 真实风险 11 只

- **89 只**：`list_status='D'` 且 `delist_date < 2016`，早于数据起点，**合理缺失**
- **11 只** `list_status='L'` 却无 daily_bar：

  | ts_code | 名称 | 上市 |
  |---------|------|------|
  | 601136.SH | 首创证券 | 2022-12-22 |
  | 601156.SH | 东航物流 | 2021-06-09 |
  | 601138.SH | 工业富联 | 2018-06-08 |
  | 601155.SH | 新城控股 | 2015-12-04 |
  | 601137.SH | 博威合金 | 2011-01-27 |
  | 601158.SH | 重庆水务 | 2010-03-29 |
  | 601139.SH | 深圳燃气 | 2009-12-25 |
  | 300485.SZ | 赛升药业 | 2015-06-26 |
  | 300465.SZ | 高伟达 | 2015-05-28 |
  | 300450.SZ | 先导智能 | 2015-05-18 |
  | 300452.SZ | 山河药辅 | 2015-05-15 |

  这 11 只都不应该缺（尤其工业富联、新城控股、先导智能是常见标的）。**怀疑 bootstrap 对 list_date < 20160101 的老股没拉**（start_date=20160101 过滤了首个数据点，又因 cursor 机制卡住）。优先级 P1。

  → **Action**：bootstrap 重跑这 11 只，验证修复；`daily_ingest_errors.csv` 有线索可以查。

### 项 2 · 交易日覆盖：154 天 < 4000 只 → 无问题

分年度分布：

| 年 | min | avg | max | < 4000 |
|----|-----|-----|-----|--------|
| 2016 | 2551 | 2666 | 2877 | 244（全年）|
| 2017 | 2867 | 3081 | 3284 | 244 |
| 2018 | 3167 | 3382 | 3572 | 243 |
| 2019 | 3568 | 3654 | 3786 | 244 |
| 2020 | 3774 | 3958 | 4193 | 154 |
| 2021+ | 4196+ | ≥4456 | | 0 |

A 股上市总数 2020Q1 才从 3700+ 突破 4000。阈值选错。交叉验证 `n_traded vs n_listed`：2020 年之后每个交易日差距 < 100 只，完全健康。

→ **Action**：无需处理，知识点写入。

### 项 3 · 财务季度连续性：2506 只无 fina_indicator → 系统性稀疏

- 无财报股票的板块分布（前十）：300（436）/ 002（410）/ 600（343）/ 688（276）/ 603（273）/ 301（197）/ 000（168）/ 920（124）/ 601（87）/ 001（66）
- 各板块均有缺失，**非板块特异**。抽样 300 板块随机 10 只：2012 上市的"蓝英装备"、2009 上市的"神州泰岳"、2016 上市的"精测电子"都无财报
- 同时验证：300333.SZ（雪球常规标的）**有完整财报**

**推断**：Tushare `fina_indicator` 接口在 2000 积分档下，对部分股票的历史覆盖不完整，是**数据源配额限制**而非管道 bug。继续升积分或用 akshare 补数据可解决，但对**量化策略可用性影响有限**（纯多头 + 技术面为主的策略不依赖财务因子；M2b 存储赛道 S3 打分器只涉及 8 只池内股票，**可逐只验证**）。

→ **Action**：
1. M3 框架层在涉及基本面因子时，skip `fina_indicator` 无记录的股票
2. M2b S3 打分器前，单独验证池内 8 只的 fina_indicator 完整度（见下面 §4）
3. 降级 P2，不阻塞 M3

### 项 4 · 停复牌一致性：✓

- `vol=0` 行 0
- 非交易日却有数据 0
- `vol=0 且 amount>0` 0

说明 Tushare 停牌日**不返回记录**（而非 vol=0），这是策略层要注意的：**计算日收益时遇到非连续 trade_date，必须用前复权复权价还原，而不是假设连续**。

→ **Action**：在框架的 ts 重采样层加入"停牌断点识别"。

### 项 5 · 复权一致性：2543 异常 → 实际风险 158 行

市场分布：

| 市场 | 异常行数 |
|------|---------|
| BJ（北交所） | 2385 |
| SZ（深市） | 94 |
| SH（沪市） | 64 |

- **BJ 2385 行**：样本全部呈现 `prev_adj_close = 1.0` → `adj_close = 几百`。说明 **Tushare 对北交所 adj_factor 的初始值处理异常**（把新股第一个 factor 给成 1.0 而不是真实倍率，导致与 close 相乘后跳变）。已知 quirk
- **沪深 158 行**：分两类
  - 极端涨：000670 `22.7→133.6`（+488%，2022-08-22 似真的**缺了除权 factor**）
  - 极端跌：000622 `4.49→0.48`（-89%）、600766 `41.6→1.48` → **很可能是真正的除权日，adj_factor 滞后**

**抽检 4 个**：000670.SZ / 688615.SH / 300939.SZ / 688026.SH 都是上市后短期内的跳价，**疑似上市首日 / 停复牌后首日的 factor 未同步**。

→ **Action**：
1. **策略层硬规则**：任何日收益 |ret| > 30% 标为 `suspect`，策略按需跳过（不要 NaN 丢弃）
2. M3 框架加入 `check_adj_gap(ts_code, date)` 函数，在回测每个 rebalance 点扫一下，遇到 suspect 日报错而非静默
3. 样本池**默认剔除 BJ 市场**（纯多头策略不缺流动性标的，北交所无价值）

### 项 6 · 财报去重：✓

## 3. M3 框架层防御清单

进 M3 前，必须在回测框架的**数据接入层**（`quant_data/api.py`）内置以下约束：

- [ ] **默认样本池规则**：剔除 `list_status='D'`、剔除 BJ 市场、剔除"active 但无 daily_bar"的 11 只、默认允许剔除缺 fina_indicator 的股票（可选开关）
- [ ] **停牌断点识别**：`get_price_series(ts_code, start, end)` 在返回前，检测 trade_date 相邻 gap > 交易日历预期 → 标 `halted_days`
- [ ] **复权跳变告警**：计算日收益时，对 |ret| > 30% 的记录不直接 NaN，标记为 `adj_suspect=True`，策略决定跳过或报错
- [ ] **财务前瞻防护**：fina_indicator 必须用 `ann_date`（而非 end_date）做 as-of 过滤（bootstrap 已按此入库，框架层不能再误用 end_date）

上述 4 条写入 M3 的 acceptance 清单。

## 4. M2b 支线额外验证

M2b 存储赛道依赖池内 8 只股票的 S3（财务）/ S4（技术）打分器。本次体检结论对 M2b 的影响：

- S4（技术面）：daily_bar / adj_factor 对非 BJ 主流标的可用，**池内无北交所**，✓
- S3（财务）：需单独抽查池内 8 只的 `fina_indicator` 完整度。脚本：

  ```sql
  SELECT ts_code, COUNT(*) AS n_reports, MIN(end_date), MAX(end_date)
  FROM fina_indicator
  WHERE ts_code IN ('688008.SH','000021.SZ','603986.SH','300223.SZ',
                    '688110.SH','001309.SZ','301308.SZ','688525.SH')
  GROUP BY 1;
  ```

  → 在 M2b 启动 S3 打分器编码前先跑一次。
