## 2. Spike 链完整时间线

10+ 个 Spike 一日跑完，每个 spike 都是**"一个单变量实验 + 一个诊断"**。

```
A  Top1 momentum 日频           -99.95%  ✗  方向错 + 极端样本
B  Top10 momentum 月频          -99.10%  ✗  方向错
C  B + 顺势闸                    -96.35%  ✗  方向错（闸门救不了）
D  B 反号 → 反转                 -39.45%  ⚠  方向对，无闸
E  D + 反向闸                    +16.65%  ◯  首次正收益
F  E + 行业两层（行业动量 + 行业内反转） +67.70%  ◯  首次跑赢 HS300
G  F + ATR 止损                  +21.59%  ✗  反效果（杀 V 底 α）
H  F + 残差反转（剥市场 β）       +32.97%  ◎  看似跑输 F，但样本外更稳
H3 H + 多窗合成 5/10/20          +52.83%  ⭐  综合最强（Sharpe 0.13 / MDD 41%）
```

**时间成本**：引擎搭建 ~4 小时（M3），单个 Spike 平均 ~30 分钟（规格 + 改代码 + 回测 + 诊断报告）。全部 10 个 Spike 单日完成是因为引擎设计让"改 30 行跑一个实验"成为可能。

## 3. 五个反直觉发现

每一个都**打破了进入 Spike 前的假设**，都是方法论贡献。

### 3.1 "裸动量" 在 A 股不是弱化版策略，是反向策略
**假设**：动量不够强 → 加过滤就好。
**实际**：20 日动量 ICIR **-0.244**（BigQuant 实测），数学上**做多 Top 动量 = 做反向反转**，复利下必然亏光。
**证据**：Spike A 累计 -99.95%，B -99.10%，C -96.35%。不是参数问题，是**方向错**。
**教训**：**进入任何回测前先验证信号的 IC 符号**。20 日 "动量" 在 A 股 ≤1 月 = 反转因子的空头。

### 3.2 市场状态闸门**方向有对错**
**假设**：大盘在均线上 = 趋势向上，适合开仓。
**实际**：反转因子在**震荡/熊市有效，单边牛市溃败**。Spike C 的顺势闸（HS300 > SMA60 开仓）在错的方向上过滤，反而把 2017/2019 的亏损放大。
**修正**：Spike E 把闸门反转（震荡时开仓）→ 累计从 -96% 翻到 +16%。**同一个闸门规则，方向颠倒收益差 113pp**。
**教训**：**状态闸门的"开仓方向"是因子本身属性决定的**，不是常识性的"涨了才买"。

### 3.3 ATR 止损在反转策略里是**反效果**
**假设**：加止损能降 MDD。
**实际**：Spike G（F + ATR 2.0）累计 -46pp，**MDD 只降 0.34pp**。ATR 倍数扫描（1.5/2.0/2.5/3.0/4.0/∞）单调趋势：**越松越好，最优 = 没有止损**。
**根因**：反转假设 = "跌的会反弹"，ATR 假设 = "继续跌就砍"，**两者方向相反** → ATR 正好在 V 形底把仓位卖飞。
**教训**：**止损逻辑必须和信号逻辑一致**。反转类用止损 = 自断 α。这条与 [[m4-prior-art]] §3.4 共同模式第 5 条印证（"纯因子策略止损用得少，靠事前分散"）。

### 3.4 "回测最佳" 可能是运气，**样本外才见真章**
**假设**：Spike F 累计 +67.70% 是合理 baseline。
**实际**：Spike H（剥市场 β）累计 +32.97% 看似跑输，但**剔除 2016 这一年**后 H 样本外 +24.22% 反而胜 F 的 +8.66%。
**根因**：F 的 +67% 里 2016 单年贡献 +51.79% —— 那年是熔断 + 市场整体反弹，F 买跌幅最大的股票 = 抄底全市场 β 反弹。这是**β 贡献**（运气暴露），不是 α。
**教训**：**看 F 觉得是 alpha，看 H 才知道是 β + 选股 alpha**。样本内"最佳参数"经常是对非典型样本的过拟合。**每个策略都要做 ex-2016（或 ex-任何极端年）的稳定性检查**。

### 3.5 多窗合成的**"大胜覆盖小输"**
**假设**：多窗合成应该在所有场景下都更好（多样化原则）。
**实际**：Spike H3 比 H 在 6 年胜（2019/2021/2022/2024/2025/2026）、5 年输（2017/2018/2020/2023）。但净值上 H3 胜 20pp。
**根因**：多窗在**行情切换 / 跳水反弹**大胜（2021 +17.4pp, 2025 +13.9pp, 2024 +5.8pp），在**缓慢单向趋势**小输（2017 -3.8pp, 2018 -11.3pp）。**大胜的幅度远大于小输的幅度**，因为 A 股行情切换比单向趋势更激烈。
**教训**：**不要追求"全场景最优"**，要追求"劣势场景可接受 + 优势场景爆发"。A 股的非对称性（下跌慢、反弹快）天然对"捕捉切换"的策略有利。

## 4. 量化策略开发方法论提炼

以下 7 条是跨项目复用的**"工程和研究模式"**，来自 Spike 链的实际教训。

### 4.1 "调研先行" 比 "跑 1000 次回测" 更省时
**证据**：做 Spike A/B/C（纯动量三连跪）花了 1 小时。**花 30 分钟看 BigQuant 的 IC -0.244**，可以直接跳到 Spike D（反转）起步。
**模式**：
- **进任何回测前先查学术 / 开源社区结论**（调研 §九引用的 prior-art skill）
- 具体指标：IC / ICIR / IR 的**符号和强度**，不只是"效果如何"
- 调研不是阅读综述，是**抓具体数字**

### 4.2 Spike 链 = 单变量实验 + 归因
**模式**：每个 Spike **只改一件事**，和前一版对照。
- A (Top1) → B (Top10) = 改"持仓集中度"
- B (动量) → D (反转) = 改"信号方向"
- E (无行业) → F (行业两层) = 改"样本空间"
- F (raw) → H (残差) = 改"信号去噪"
- H (单窗) → H3 (多窗) = 改"时间尺度"

每步**单变量差异明确**，归因没有歧义。如果一步改两件事，回测出来好坏都说不清是哪个变量贡献。

### 4.3 年度拆分 > 全样本指标
**证据**：Spike D 累计 -39% 看起来失败，但年度拆分出"震荡年全胜 / 单边牛市全输" —— 完美复现 BigQuant 的 "震荡 ICIR +0.45 / 牛市 -0.36"。**全样本指标隐藏了所有因子的时变性**。
**模式**：每个 Spike 报告必须有年度拆分表（F vs H vs H3 这种表才有决策价值）。

### 4.4 "反直觉结果" 是调研信号
**证据**：Spike G 的 "ATR 反效果" 和 Spike H 的 "看似跑输但样本外更稳"，都是**与通识预期相反**的结论。每一个都推动了后续方向的调整。
**模式**：回测出"明显好"的时候警惕运气；出"明显差"的时候**先诊断再放弃**（Spike G 如果直接放弃就不会发现 ATR 和反转的假设冲突）。

### 4.5 诚实分层：α / β / 运气
**证据**：F 的 +67% 被分解为"β 贡献 51% (2016) + α + 噪声"，H 和 H3 的数字是"剥掉 β 后的净 α"。
**模式**：每个策略必须**显式回答"你的收益来源是什么"**：
- 市场 β（买入持有）
- 风格 β（小市值 / 高 Beta）
- 行业 β（赛道暴露）
- α（剥完 β 后的残差）
- 运气（单一极端样本的贡献）

"α 和 运气" 的区分方式：**剔除极端年样本外检验**（ex-2016 重测）。

### 4.6 验收线是"质量门"，不是"是否启动"的标准
**证据**：H3 四项验收全不过，但**作为 baseline** 完全可用 —— 我们现在知道"反转 α 在 A 股的强度上限约 Sharpe 0.13"，这个信息在未来决策（加杠杆 / 配合其他因子 / 切备选方向）时极有价值。
**模式**：策略不达验收线 **≠ 失败**。它是一个**量化的 α 强度探针**，告诉你"这个方向的上限在哪"。

### 4.7 工程和研究的边界
**证据**：M3 引擎花了 4 小时搭建（`strategy(asof, bars, portfolio) -> weights` 协议 + fast_mode），让 Spike 实验每个只需 30 分钟。整体上**工程投入 vs 研究产出的比例 ~1:3**。
**模式**：
- **引擎是一次投资**：每小时引擎开发可以节省后续 3-10 倍的研究时间
- **策略是一次性的**：每个 Spike 的代码就 50-150 行，不值得过度抽象
- **一次性代码不做抽象**（CLAUDE.md §3.2）

## 5. 技术侧教训

### 5.1 引擎设计的关键决策
- **协议最简**：`strategy(asof, bars, portfolio) -> {ts_code: weight}` 五字协议让 10 个 Spike 共用
- **fast_mode 开关**：单票策略传切片、全市场策略传 reference —— 性能差 50x
- **前复权 + ann_date 防前瞻** 从 M2 就内建（不是 Spike 阶段才加）

### 5.2 调试中发现的真 bug
| Bug | 位置 | 影响 |
|---|---|---|
| Tushare 空 df 误更新 progress | `ingest/daily_bars.py` | 11 只股票首批 bootstrap 漏数据 |
| DuckDB YYYYMMDD CAST 不支持 | `universe/filters.py` | filter 计算错误 |
| build_universe 用交易日 idx 算上市天数 | `universe/filters.py` | 250 日门槛对 2016 前上市股票不生效 |
| engine 换仓时持仓无法卖出 | `backtest/engine.py` | Spike A 首跑 10 年只交易 10 笔（应 600+）|
| metrics.turnover 用归一化 nav 做分母 | `backtest/metrics.py` | 换手率出 5102970x |

教训：**Spike 之前没做的压力测试**（全市场全历史），bug 一路积累到 Spike 时才暴露。M3 的 hello-world（单票）覆盖不够。下一次：**M3 尾段加一个 "全市场 ≥3 只标的 × ≥1 年" 的冒烟测试**。

### 5.3 DuckDB + pandas 的性能拐点
- 全市场 1060 万行一次拉：3.5s（DuckDB 优势）
- pandas pivot 5800 × 2510：2.1s
- 每日字典切片 5800 个 DataFrame × 2500 次 = **死路**（之前出现过）
- 解决：`fast_mode=True` 传 reference

教训：**vectorized（矩阵化）和 iterative（每日循环）的分水岭是"策略要看多少个股"**。单标的 iterative 没问题；全市场必须矩阵化。

### 5.4 数据源的坑分级
- **硬坑**（必须修）：Tushare 空 df、DuckDB 日期格式、主键冲突
- **软坑**（接受）：Tushare 2000 积分对 fina_indicator 覆盖稀、北交所 adj_factor quirk、老股 list_date 早于数据起点
- **未知**（留档）：`update_progress` 漂移（未定位根因）

## 6. 仍未解决的问题

这些留给 M5 / 下个 project / 未来的自己。

### 6.1 策略侧
- **单因子 α 上限**：H3 Sharpe 0.13 可能就是 "20 日反转 + 行业分散 + 月频 + 反向闸" 框架下的天花板。突破需要**多因子合成**（反转 + 换手率加权动量 + 波动率）或**事件驱动叠加**
- **跳水期仍亏 -25%+**：H3 在 2024 比 F 好 6pp 但仍惨。真正救跳水的是**大盘绝对跌幅闸门**（单日/5 日跌幅 > 阈值立即空仓），不是个股 ATR
- **行业粒度**：tushare 110 行业是三级，太细。**每行业平均 50 只股票，信号噪声大**。改用申万一级 28 行业预期有改善

### 6.2 工程侧
- **pipeline Bug 1**：`update_progress` 漂移根因未定位。当前 "数据完整性扫描脚本" 可以定期跑（healthcheck.py），但不是根治
- **涨跌停过滤未实现**：hello-world 没模拟，Spike 链也没加。实盘前**必须补**（在 Spike F 的 2021 年应该会被触发多次涨停板无法成交）
- **实盘打折**：strategy-selection §六 "实盘 = 回测 × 0.75"。H3 的 +4.35% 年化 × 0.75 = 3.26%，仍跑赢 HS300 但刚到 Sharpe 0.1 量级

### 6.3 方法论侧
- **Spike 链如何提前停止**：Spike G（ATR 反效果）是 well-formed 实验，但花了 50 分钟。能否更早识别"这条路不通"？
- **验收线该怎么定**：brief §六 的 Sharpe ≥0.8 对单因子策略可能过高。业界单因子 ICIR 0.3-0.5 对应 Sharpe 约 0.5-1.0，0.8 是 top quartile
- **如何做多因子合成**：这是 M5+ 的核心话题，prior-art 调研时只看了理论，没看开源实现
