# 乐和 SCRM 集成项目 · 简报

## 背景

乐和公司同时使用两个 SaaS 平台：
- **小鹅通**：知识付费/在线教育交付平台，持有用户学习行为、付费记录、内容互动数据
- **螳螂营销云**：教育行业全链路营销 SaaS，持有广告来源追踪、线索分配、销售跟进、SCRM 私域数据

两平台数据相互独立，销售人员无法在一个界面看到"某客户从哪个广告来、买了哪门课、学到哪里了"的全貌，导致运营效率低、客户旅程断裂。

## 目标

在统一 CRM 中，以客户（手机号为主键）为中心，将小鹅通的购课/学习数据和螳螂营销云的线索/营销数据打通，实现：
1. 客户 360° 视图（广告来源 + 购买记录 + 学习进度）
2. 销售可在 CRM 内看到客户的小鹅通学习状态
3. 营销团队可按学习进度做分层运营

## 非目标

- 不重建 CRM 系统本身（对接现有或选型 CRM）
- 不做广告投放管理（螳螂的广告商对接层保持原样）
- 不替换小鹅通或螳螂的业务功能

## 范围

- 小鹅通 API 调研与数据拉取方案
- 螳螂营销云 API 调研与数据导出方案
- 数据实体映射（两平台字段 → CRM 统一字段）
- 集成架构设计（同步频率、匹配策略、冲突处理）
- CRM 选型建议（如需）

## 风险 / 未知

1. **螳螂营销云 API 不公开**：官网无法访问，文档需商务申请，开放范围未知
2. **用户匹配率风险**：微信用户未绑定手机号时，手机号匹配策略失效
3. **小鹅通 IP 白名单**：部署服务器需固定 IP，云函数/Serverless 架构需特别处理
4. **螳螂 Token 有效期**：小鹅通 token 2 小时过期，集成层需自动刷新机制
5. **CRM 选型**：目前未明确用哪个 CRM 系统（自研？飞书？HubSpot？）

## 关键信息（来自 2026-05-04 调研）

### 小鹅通 API（已较清晰）
- 认证：`client_credential` 模式，Token 2 小时过期
- 基础域名：`https://api.xiaoe-tech.com`
- SDK：PHP / Python / Java / Go（GitHub: `xiaoeteam/XiaoeApiSDK`）
- IP 白名单：必须配置
- 关键接口：用户列表、用户详情、订单列表、学习进度、打卡数据
